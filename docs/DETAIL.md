# 插件兼容巡检

DSH 升级之后，你自己安装的插件还能不能用，这件事原来没有人告诉你。这个插件补上这一步：在运行时版本变化后的第一次启动里，把非官方插件逐个查一遍，写一份报告，然后停下。

它只读。启用、禁用、更新、改源码、授权版本豁免这些动作全部留给你决定。

## 检查什么

数据全部来自插件管理器自己的结论和插件包的清单，插件不另建一套版本判定。

**装配状态。** 对每个自装 bundle 的 loader 行取 `enabled`、`fiberPhase`、`diagnostic`。`active` 说明模块导入成功、`apply` 没抛、依赖服务都在；`failed` 说明它在当前版本上起不来，诊断原文进报告。

**版本护栏。** 读插件 `package.json` 里的 `engines.dsh` 或 `@deepseek-ai/dsh-*` peer 依赖。DSH 用这两个字段在安装和激活时拦不兼容的插件；两者都没写，插件就没有任何护栏，升级后只能靠人复核。管理器报 `incompatible-version` 时，未满足的范围原文进报告；靠精确版本豁免在跑的，单列成「每次 DSH 更新都要重新授权」。

**官方按需插件。** 官方目录里按需安装的插件（如 `dsh-subagent-codex`）安装时固定在当时的运行版本上。升级 DSH 后，profile 里那份旧版本不满足新运行时的精确 peer 依赖，需要按当前版本重装。报告把这类单独列出。

**profile 残留。** `node_modules` 里指向不存在目录的链接、被选用但没有安装的 bundle、装了但不是插件包的依赖。

## 什么时候检查

每次启动都评估一次，只有下面任一条成立才真正重跑：

- DSH 版本变了（`getDshRuntimeVersion` 的值与上次记录不同）。
- 安装目录被替换（同一版本重装，看安装锚点 `package.json` 的修改时间）。
- profile 的依赖或启用列表变了。
- 上次检查没有跑完。

另外，插件管理器的任何操作完成（`plugin-manager/changed`）和 profile 配置重载（`app-boot/config-reload`）会在 1.5 秒后合并触发一次重查。手动方式有两个：工具 `plugin_compat` 的 `check`，或重启后等第一次检查。

启动后 3 秒采样；如果还有行停在 `pending`/`loading`，7 秒后补采一次，不无限等。

不会触发检查的：每条用户消息、每个回合、每次模型请求、文件系统监听。

## 结果在哪

默认写到 `~/.dsh/plugin-compat/`：

- `state.json`：上次检查的版本、安装标记、插件清单、registry 最新版本缓存。
- `report-<版本>.json`：结构化的完整报告。
- `report.md`：给人看的同一份内容。

报告文件按修改时间保留最近 3 份，旧的自动删除。`stateDir` 可改。

## 怎么读

工具 `plugin_compat` 有三个动作：

- `status`：读最近一次报告，一行一个插件，加待处理数量。
- `check`：立即重跑一次（会刷新 registry 版本查询）。
- `explain <包名>`：返回单个插件行状态、证据链和建议动作。

报告里「待处理」的计数包含：运行异常、未就绪、靠豁免运行、启用但没有版本护栏、官方按需插件落后、profile 残留。

## 开发版与正式版

本地是 prerelease（版本号带 `-rc`）时，报告会标出来。开发版上有一件事需要分开看：插件按稳定版写范围（`^0.2.2`）时，DSH 在 rc 运行时上会判它不满足，这是版本范围的正常语义，把 0.2.2 转正之后就恢复兼容。报告把这类归入「装配 + 声明」两层，不当成插件坏了。

## 限制

- Client 半（浏览器内加载的 UI）没有验证。Host 侧全部 `active` 时，带 `dsh.client` 的插件页面仍可能空白；报告会点名列出来。
- upgrade-guide 契约比对还没做。方法签名改名、slot prop 改名这类问题这份报告看不出来。
- 定时查询新版 DSH 还没做。报告只在触发检查时顺带记一次 registry 的 `latest`。
- 插件本身出问题时（它也在被检查的清单里），报告仍留在磁盘上，重启后可以看上一次的结论。

## 配置

在 `cordis.patch.yml` 的 `plugin-compat` 行里改：

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `checkOnBoot` | `true` | 启动后是否自动评估 |
| `checkLatest` | `true` | 是否查询 registry 上 dsh 的最新版本 |
| `stateDir` | `~/.dsh/plugin-compat` | 状态与报告目录 |
| `reportKeep` | `3` | 保留几份历史报告 |
